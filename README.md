# 寸进链 · CunjinChain

> 把每日打卡的积分与成就写成区块链上的**可验证凭证**，让努力能被外人独立核验。

**在线演示 → <https://cunjin-chain.surge.sh>**
打开即用，不需要安装任何东西，也不需要数据库。

[用户端](https://cunjin-chain.surge.sh/) · [链浏览器](https://cunjin-chain.surge.sh/chain) · [管理端](https://cunjin-chain.surge.sh/admin) · [凭证验真](https://cunjin-chain.surge.sh/verify)

---

## 这是什么

寸进链是一个每日打卡积分平台。与普通打卡产品的区别在于：**积分、徽章、兑换、押注、捐赠**这类动作在写入业务库的同时，会生成一笔带 **Ed25519 签名**的链上交易，由自研的轻量区块链打包出块。

于是三本账可以互相对账：

| 账本 | 存在哪 | 含义 |
| --- | --- | --- |
| 业务流水 | `point_ledger` 表 | 这次动作该发多少分 |
| 账户台账 | `account` 表 | 用户当前余额 |
| 链上余额 | 重算全部链上交易 | 把该用户所有交易重算一遍得到的余额 |

三者对不上，就说明有数据被绕过系统改过。管理端的「三方对账」页就是干这个的。

## 四个端

| 端 | 入口 | 面向谁 | 能做什么 |
| --- | --- | --- | --- |
| 学习者端 | `/` | 学生 | 打卡、任务、徽章、商城、押注、自习室、榜单 |
| 链浏览器 | `/chain` | 任何人 | 看区块、查交易、**跑全链校验**、进「篡改实验室」 |
| 运营管理端 | `/admin` | 运营 | 概览、用户、积分规则、风控、对账、审计、链运维 |
| 凭证验真页 | `/verify` | 外人（免登录） | 输入凭证号，浏览器端用 WebCrypto 独立验真 |

## 三个技术亮点

**1. 自研轻量区块链**
SHA-256 链式哈希 + Merkle 树 + Ed25519 交易签名 + 工作量证明出块。不依赖任何第三方链平台，没有代币经济，是「存证」而非「发币」。

**2. 可独立验真的凭证**
凭证携带序列号、验真码，以及**该笔交易在区块内的 Merkle 路径**。验真页在浏览器端用 WebCrypto 重算 Merkle 根、与块头比对并验证 Ed25519 签名 —— 结论不依赖对服务端的信任。

**3. 篡改实验室**
把六种篡改方式（改区块时间戳 / 改交易金额 / 改交易顺序 / 改前一区块哈希 / 改 Merkle 根 / 改 nonce）做成可视化实验，改完点校验，系统会精确报出**第一个出错的区块高度**。

## 技术栈

| 层 | 选型 |
| --- | --- |
| 后端 | Node.js 18+ / Express 4 |
| 数据库 | MySQL 5.7（23 张业务表 + 5 个视图） |
| 密码学 | Node 内置 `crypto`：SHA-256、Ed25519 |
| 前端 | 原生 ES Module + 原生 CSS，图表与图标**全部手写 SVG**，无框架、无 CDN |
| 讲解视频 | Python（edge-tts 配音 + Pillow 逐帧合成）+ Chrome DevTools Protocol 录屏 |

> 刻意不用前端框架，是为了让整套系统**离线也能跑**，答辩现场不需要网络。

## 本地运行

### 前置条件

- Node.js ≥ 18
- MySQL 5.7

### 第 1 步 · 导入数据库

```bash
mysql -h127.0.0.1 -P3307 -uroot -p123456 < sql/cunjin_chain-full.sql
```

一条命令建库 `cunjin_chain`、建 23 张表、灌入全量演示数据（约 200 个区块 / 4 900 笔交易）。

> 只要表结构不要数据？用 `sql/schema.sql`。

### 第 2 步 · 装依赖并启动

```bash
npm install
node server.js
```

默认端口 **<http://127.0.0.1:8901>**。

### 第 3 步 · 打开四个端

| 端 | 地址 |
| --- | --- |
| 学习者端 | <http://127.0.0.1:8901/> |
| 链浏览器 | <http://127.0.0.1:8901/chain> |
| 运营管理端 | <http://127.0.0.1:8901/admin> |
| 凭证验真页 | <http://127.0.0.1:8901/verify> |

## 在线演示版是怎么做的

线上版是**只读**的（页面底部有提示条）：可以浏览、可以点开每个区块、可以跑全链校验和篡改实验室，但签到 / 铸造 / 兑换这类写操作不会落库。

做法：先在真实 MySQL 环境下用无头浏览器把四个端实际发出的全部 `/api` 请求与响应录成快照，演示版只负责托管前端 + 回放这份快照。

- `deploy-static/` —— 纯静态版，浏览器端 `demo-shim.js` 拦截 `fetch` 回放（线上跑的就是这个，任何静态托管都能用）
- `deploy-online/` —— Node 回放版，`node server.js` 即可

重新生成静态包：`node tools/build-static.js`

## 说明与取舍

1. **不做真实转账**。本项目是「存证」而非「发币」，链上没有代币经济，不需要钱包，也不涉及任何真实资产。
2. **出块由服务端定时触发**，不是全网共识。这是刻意取舍 —— 目标场景是单运营方的中低频业务，用轻量自研链换取可验证性，而不是追求去中心化。
3. **前端不引框架 / CDN**，为了保证离线可演示；代价是部分交互需要手写 DOM 更新。
4. **线上演示版只读**，完整可写功能请在本地运行（见上方「本地运行」）。
